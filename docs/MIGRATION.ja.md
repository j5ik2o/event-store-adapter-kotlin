# 旧Kotlin公開操作とDynamoDBデータの移行

旧Aggregate/Eventへの継承、version引数、シャード・key resolver設定、旧Java内部生成入口、getEventsByIdSinceSequenceNumberを廃止します。Javaのcore封筒とEventStoreConfig、型引数2つのKotlinストア、getEventsByIdSinceSeqNrへ切り替えます。シリアライザは生成時に決め、最新読取は封筒の有無と独立したヘッド番号を保ちます。

旧Kotlin/Java配置を新生成入口から直接開くことはできません。[共通実装計画](https://github.com/j5ik2o/event-store-adapter/blob/main/docs/plan/implementation-plan.md)に従い、利用者が変換して書き直します。Rust第3版向けの移行ツールはこの配置へ適用しません。

1. 旧ストアへの書き込みを停止し、旧表と設定を読取・検証用に保持します。
2. 旧版ライブラリと元のシリアライザ・キー設定で読みます。各集約のジャーナルを最後まで読めたことと1からの連続性を確認します。旧イベント取得は1ページで止まる場合があるため、必要なら旧配置を理解した保存先の直接読取で全件性を確認します。欠番は書き直す前に利用者が解消します。
3. 旧識別子とペイロードからtypeName/value、イベント内容、occurredAt、manifest、集約状態への対応を利用者が明示します。旧ペイロード内のライブラリメタデータは、ドメインの対応に従って取り除きます。manifestは明示するか既定の空文字列を使います。ハイフンを含む型名は明示的に対応付けます。失われた識別子・型情報を推測せず、旧ミリ秒時刻から失われたナノ秒を補いません。
4. [新配置](DATABASE_SCHEMA.ja.md)の独立journal・snapshot・head表を外部で作成します。EventStore.ofDynamoDBまたはEventStoreAsync.ofDynamoDBで3設定項目を初期化・照合します。旧表と新表を組み合わせません。
5. 新公開追記操作を使い、各集約を1から連続する番号順で書き直します。対応するスナップショットがなければpersistEvent、同じ番号まで適用した状態がある場合だけpersistEventAndSnapshotを使います。旧versionを渡さず、最終番号から作成せず、連続追記でヘッドを構築します。
6. 封筒全要素・ペイロード・スナップショットの有無・ヘッド番号を読み戻します。全件リプレイと別集約の独立性を確認してから、利用側を新ストアへ切り替え書き込みを再開します。この確認が終わるまで旧データを保持します。

ラッパーは旧配置読取、互換alias、fallback、自動変換を提供しません。メモリはプロセス内の寿命なので、実行中状態を移す場合は新しい保存先を作り、変換済みイベントをリプレイします。正式配布と版番号の変更は、別途オーナーが管理する作業です。
